# 题镜确认按钮流程设计

## 目标

所有自动答题流程统一为“选择答案 -> 点击确认 -> 检测页面变化”。自动模式不设置固定题数上限，稳定换页后持续识别下一题，直到用户手动停止。

## JSON 协议

- 新增 `confirm_box: [x,y,width,height] | null`，表示当前题“确认”按钮的百分比坐标。
- `confirm_box` 缺失或为 `null` 时，原生无障碍服务按文字“确认”定位。
- 保留 `next_box` 的解析兼容性，但原生确认流程不再依赖该字段。
- `next_action` 继续作为展示字段，原生状态机不信任它来决定动作。

## 原生状态机

- 自动模式检查点为 `ANSWERS -> CONFIRM_BASELINE -> CONFIRM -> PAGE_POLL`。
- 单选、判断题点击一个答案后执行确认；多选题依次点击全部答案后执行确认。
- 选完答案后先截取选中状态作为确认前基线，避免把勾选样式变化误判成换题。
- 确认成功后使用确认前基线、帧签名和稳定性阈值检测页面变化。
- 第 1 至 99 题在页面稳定后题号加一并继续。
- 任意题号在确认后的页面稳定后题号加一并继续，不设置 `WAITING_MANUAL_SUBMIT` 终态。
- 暂停、停止或失败会取消当前截图、模型请求、确认手势和后续轮询。

## 手动模式

手动模式仍只展示答案。用户自行选择答案并点击确认，然后再次点击题镜悬浮按钮识别下一题。

## 验证

- JSON 解析覆盖 `confirm_box` 合法、缺失和越界场景。
- 协调器覆盖三种题型的确认动作、文字后备、确认前基线、跨过第 100 题继续运行、确认失败重试和暂停恢复。
- JavaScript 兼容层同步解析并执行 `confirm_box`。
- 完整 JavaScript、Kotlin 单元测试和 APK 构建通过。
