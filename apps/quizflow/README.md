# 练题流 QuizFlow · Android 0.8.0 试用版

基于 [futureYYY/TiJing](https://github.com/futureYYY/TiJing) 主分支 2d2da078 修改的安卓练习页面辅助工具。保留 MIT 许可与原作者署名；衍生版使用独立名称、包名与图标。

## 使用

1. 安装 APK。进入「模型设置」，填写兼容 Chat Completions 的接口地址、视觉模型名称和 API Key。
2. 选择「视觉模型直接解题」或导入自己的 JSON 题库。题库模式仍需要视觉模型读图。
3. 在「运行策略」选择自动刷题，设置翻题方式。默认点击本题确认或下一题按钮；没有按钮时可指定左、右、上、下滑动。
4. 如需最后交卷，手动开启「最后自动提交」（默认关闭）。题库未命中时是否由模型解题也可切换。
5. 启用悬浮识题，授予无障碍、悬浮窗与屏幕采集权限。打开需要操作的题目页面，点悬浮按钮开始。
6. 运行中保持原应用在前台。可以随时从悬浮窗暂停或停止。

## 本次新增

- 逐步观察循环：截图→识别题目与当前选中状态→点击/滑动→重新截图核对。
- 连续答题、独立下一题按钮、四方向滑动翻题、长题滚动收集。
- 多屏截图用于补全题干；仅最后一张截图提供可点击坐标。
- 本地题库按选项文字匹配答案，避免选项顺序变化造成错点。
- 已选答案保留校验记录，多选题不重复切换已核实的正确选项。
- 同题模型答案变化、低置信度、选中状态不明、页面无响应等情况自动暂停。
- 自动交卷：末题或答题卡→交卷→确认弹窗→成功页核验→停止屏幕采集。
- 只有页面明确显示未答题数为 0，或从 1 到总题数的每题均已由本次运行核实，才继续交卷。明确有未答题会暂停。
- 动作绑定原应用；暂停和停止后，迟到的模型响应不能继续点击。

## 实际边界

这是可安装的试用版本，不是已经在具体长江雨课堂页面上验证过的成品。没有使用用户的雨课堂账号、真实作业或真实手机测试；实际页面的题号、按钮、勾选样式可能需要适配。

- API 必须支持图片输入；只有文字能力的模型不能直接使用。
- 每次点击后的复核也会调用模型。长题会发送多屏截图，调用费用和延迟高于只识题一次。
- 截图只放在运行内存中，不保存到相册；会发送给你配置的 API 服务。Key 存在 App 本地数据中。
- 目前自动模式面向单选、多选和判断题，不实现填空输入、主观题编辑。
- 长题最多保留 8 张上下文截图；默认每题最多滚动 12 次。超出、混题或信息不完整时暂停。
- 提交成功必须由页面明确提示；不能根据点击成功就声称已经提交。
- 自动模式使用独立的多屏识别协议；可通过「自动模式补充要求」调整说明，原有视觉提示词仍供手动辅助使用。
- 没有内置模型 Key、内置题库或雨课堂账号，不绕过平台登录与页面限制。

## 题库格式

答案选项必须带完整文字，不能只有字母。索引从 0 开始。例：

```json
{"questions":[{"id":"q1","question":"题干","type":"single","answer_indices":[1],"options":[{"index":0,"text":"选项甲"},{"index":1,"text":"选项乙"}]}]}
```

在题库页导入。先用几道自测题核对识别、勾选、翻题和最后确认的实际效果。

## 构建与测试

需要 Node 22、完整 JDK 17、Gradle 8.7、Android SDK 35 / Build Tools 35.0.0。

```bash
npm ci
npm run build
node scripts/sync-android-assets.mjs
npm test
gradle -p android :app:testProdDebugUnitTest :app:assembleProdRelease
```

产物：`android/app/build/outputs/apk/prod/release/app-prod-release.apk`。

仓库提供 GitHub Actions 构建流程，可在上传到自己的仓库后运行。默认构建使用开发签名；正式分发请自行配置 release 签名，并保留密钥供后续更新。

原项目说明另存于 `UPSTREAM-README.zh-CN.md`，其中关于原版功能与下载地址的说明不代表本修改版。
